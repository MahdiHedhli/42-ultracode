# Data Model: 001 Internal Loop

## Run

| Field | Meaning | Validation |
| --- | --- | --- |
| `run_id` | Stable identifier | Generated by controller; immutable. |
| `objective` | Human-approved engineering objective | Non-empty bounded text. |
| `state` | Current lifecycle state | Derived from event replay. |
| `iteration` | Number of submitted planner instructions | Monotonic, controller-owned. |
| `max_iterations` | Upper bound | Set at creation within controller ceiling; never mutable by model. |
| `policy` | Frozen controller rules | Serialized at creation; no planner/worker mutation tool. |
| `created_at` / `updated_at` | Audit timestamps | Controller-generated UTC timestamps. |

## Instruction

| Field | Meaning | Validation |
| --- | --- | --- |
| `instruction_id` | Stable handoff ID | Controller or caller UUID; unique within run. |
| `goal` | Work objective | Required non-empty text. |
| `context` | Relevant bounded background | Required list/text content. |
| `constraints` | Non-negotiable limits | Required list/text content. |
| `done_when` | Completion conditions | Required non-empty text. |
| optional file/test/skill fields | Execution guidance | Relative paths and string lists only where applicable. |

## Execution Result

| Field | Meaning | Validation |
| --- | --- | --- |
| `status` | `completed`, `partial`, `blocked`, or `failed` | Required allowed value. |
| `summary` | Concise outcome | Required non-empty text. |
| `evidence`, `tests`, `commands` | Reported evidence | Structured arrays; commands are never executed by controller. |
| `changed_files` | Files claimed changed | Workspace-relative, no absolute paths or traversal. |
| `commit` | Optional revision reference | Optional string. |
| `blockers`, `questions`, `remaining_uncertainty` | Honest limitations | Arrays of strings. |
| `recommended_next_action` | Suggested next step | Required non-empty text. |

## Event

| Field | Meaning |
| --- | --- |
| `event_id` | Globally unique event ID. |
| `run_id`, `sequence` | Strict per-run ordering. |
| `type` | Controller-defined event type. |
| `actor` | `planner`, `worker`, `control`, `system`, or `human`. |
| `payload` | Canonical, redacted event data. |
| `idempotency_key` | Operation delivery identity. |
| `previous_hash`, `event_hash` | Tamper-evident per-run hash chain. |
| `created_at` | Controller-generated UTC timestamp. |

Events are append-only. SQLite triggers prevent ordinary update/delete attempts;
replay validates ordering and hashes. This is tamper-evident only against accidental
or unsophisticated modification because a local host administrator can replace the
database and recompute hashes.

## Turn Lease

| Field | Meaning |
| --- | --- |
| `run_id` | One active lease per run. |
| `worker_id` / `lease_token` | Current worker identity and bearer token. |
| `expires_at` | UTC lease expiry. |

An expired lease produces a recovery event and returns a claimed instruction to
the ready queue. The bearer token lives only in the active lease/idempotency
storage needed for a safe retry; it is deliberately excluded from immutable
events and history responses. A resumed paused worker never regains a stale
lease automatically.

## Feature Loop frontier binding

### Verified prompt identity

The verified identity is a sealed in-memory capability containing the exact
prompt commit, repository-relative path, calculated SHA-256, adjacent sidecar,
parsed envelope, immutable registry-selected authorization policy, and proven
control-base ancestry. It is created only by the Git transport and is required
directly by lease acquisition. Every authorization field is retained and must
match the trusted profile exactly; prompt text cannot authorize itself.
The trusted profile is selected from a closed code-reviewed registry by stable
policy ID. Its canonical SHA-256 and ID are sealed into the verified identity
and persisted in frontier metadata so replay/binding validation does not trust
caller-supplied authorization values.
The D4 registration is a separate immutable registry entry whose canonical
identity permits only checkpoint-free read-only investigation. It does not
change the currently selected execution policy or grant D4 execution authority.
The D7 readiness registration binds a distinct 42 source repository, readiness
phase, planner gate, and bounded mutation scope. It retains unconditional
checkpoint, inference, and automatic-posting prohibitions and grants no live
browser/chat capability. Its ID and digest may be persisted in a frontier
binding, but resolved chat aliases and browser capabilities remain invalid
durable data.

### Durable parent identity

For sequence 1 and later, `latest_response` includes path, SHA-256, status,
machine model, sequence, and commit. `latest_prompt` includes path, SHA-256,
and commit. Missing or mismatched fields fail closed.

### Resolved alias capability

A resolved alias has no dataclass fields or instance dictionary and refuses
JSON encoding, generic conversion, copying, and pickling. Only its explicit
transport method can reveal the private value; it is invalid in all durable
payloads.

| Field | Meaning |
| --- | --- |
| `feature_id`, `machine_model`, `sequence` | Exact planner-issued frontier. |
| `prompt_commit`, `prompt_sha256`, `response_path` | Immutable Git artifact identity. |
| `result_identity` | Durable controller result associated with publication. |

The binding is an alias-free controller artifact. Resolved local roots, topics,
thread URLs, credentials, and checkpoint locations are not fields. The adapter
projects prompt-control states without adding or changing core `RunState`
values.

## States and Legal Progression

```text
NEW → PLANNING → READY_FOR_CODEX → CODEX_RUNNING → CODEX_COMPLETE → REVIEWING
                                                │                   ├→ READY_FOR_CODEX
                                                │                   ├→ HUMAN_REQUIRED
                                                │                   ├→ FAILED
                                                │                   └→ COMPLETE
                                                └→ READY_FOR_CODEX (expired lease recovery)

any non-terminal state → PAUSED → prior safe state
any non-terminal state → STOPPED
```

`HUMAN_REQUIRED`, `FAILED`, `COMPLETE`, and `STOPPED` are terminal in v0.1.
Pause preserves the safe resume target in its event payload. Replaying all events
is the canonical way to derive state; the `runs` row is a query cache.
